مدار — راهنمای نصب از صفر (نسخه 2.3.0)
=======================================

مدار روی گوگل اجرا می‌شود: داده در یک Google Sheet، برنامه در Apps Script همان شیت،
فایل‌ها در Google Drive و جلسات در Google Calendar و Meet. سرور یا هاست جداگانه لازم نیست.
زمان لازم: حدود ۲۰ دقیقه.


چه چیزهایی لازم است
--------------------
  • یک حساب گوگل (همان حسابی که می‌خواهید صاحب داده‌ها باشد؛ ترجیحاً حساب سازمانی خودتان).
    همه‌ی مراحل را با همین یک حساب انجام دهید.
  • سه فایل این بسته:
      Code.gs           سرور: شیت، دسترسی‌ها، ورود، تقویم، ایمیل‌ها، ایمپورت
      Index.html        خود اپ (یک فایل بزرگ حدود ۱.۵ مگابایت)
      appsscript.json   تنظیمات و مجوزهای اسکریپت
  • یک مرورگر دسکتاپ (Chrome پیشنهاد می‌شود).


مرحله ۱ — ساخت شیت
-------------------
 1. به sheets.google.com بروید و یک Spreadsheet خالی بسازید.
 2. نامش را «مدار» بگذارید.
 3. منوی Extensions ← Apps Script. یک برگه‌ی تازه با ویرایشگر کد باز می‌شود.
 4. بالای ویرایشگر، نام پروژه (Untitled project) را به «Madar» تغییر دهید.


مرحله ۲ — گذاشتن سه فایل
-------------------------
 1. ⚙️ Project Settings (منوی چپ) ← تیک «Show "appsscript.json" manifest file in editor» را بزنید.
 2. برگردید به Editor (آیکن <> در منوی چپ).
 3. Code.gs: روی فایل Code.gs کلیک کنید ← Ctrl+A ← Delete ← کل محتوای Code.gs این بسته را بچسبانید.
 4. appsscript.json: این فایل را خودتان نسازید (با + نسازید). بعد از تیک بند ۱، خود گوگل آن را
    در فهرست Files نشان می‌دهد. روی همان کلیک کنید ← Ctrl+A ← Delete ← محتوای appsscript.json را بچسبانید.
    ⚠ اگر متن آن را در یک فایل .gs (مثل Untitled.gs) بچسبانید، خطای
    «SyntaxError: Unexpected token ':'» می‌گیرید؛ آن فایل را پاک کنید (⋮ ← Delete).
 5. Index.html: کنار «Files» روی + ← HTML ← نامش را دقیقاً Index بنویسید (بدون .html) ← Enter.
    داخلش Ctrl+A ← Delete ← کل محتوای Index.html را بچسبانید. (چسباندن چند ثانیه طول می‌کشد.)
 6. Ctrl+S. کنار هیچ فایلی نباید نقطه‌ی نارنجیِ «ذخیره‌نشده» بماند.
 ✔ چک: در Code.gs با Ctrl+F عبارت MADAR_VERSION را پیدا کنید ← باید '2.3.0' باشد.


مرحله ۳ — اجرای setup
---------------------
 1. بالای ویرایشگر، از فهرست توابع «setup» را انتخاب کنید ← ▷ Run.
 2. گوگل اجازه می‌خواهد: Review permissions ← حسابتان ← اگر «Google hasn't verified this app» دیدید:
    Advanced ← Go to Madar (unsafe) ← Allow.
    (اسکریپت مال خودتان است؛ این پیام برای همه‌ی اسکریپت‌های شخصی نمایش داده می‌شود.)
 3. به برگه‌ی شیت برگردید: پیغام‌ها را بخوانید و یادداشت کنید:
      • «کلید پشتیبان» (برای ورود اضطراری)
      • رمز اولیه‌ی تیم: Madar@1405
 نتیجه: همه‌ی تب‌ها ساخته می‌شوند (Tasks، FollowUps، Mizito، MizitoMentions، Contacts، Meetings،
 History، Config و…). شما «مدیر برنامه» با دسترسی کامل هستید و CPTO (جلیل علیزاده) هم تعریف شده است.


مرحله ۴ — انتشار اول: «Madar Team» (لینک اصلی و API)
-----------------------------------------------------
 1. بالا سمت راست: Deploy ← New deployment.
 2. کنار «Select type» روی ⚙️ ← Web app   (Library نه!)
 3. تنظیمات:
      Description:     Madar Team
      Execute as:      Me (ایمیل خودتان)
      Who has access:  Anyone          (نه «Anyone with Google account»)
 4. Deploy ← زیر «Web app» آدرس URL را Copy کنید (نه Deployment ID).
 ✔ چک: آدرس با https://script.google.com/ شروع و با /exec تمام می‌شود.


مرحله ۵ — ثبت آدرس
------------------
 1. ⚙️ Project Settings ← پایین صفحه «Script Properties» ← Add script property:
      Property:  API_URL
      Value:     آدرس مرحله ۴
    ← Save script properties.
 2. برگردید به Editor ← از فهرست توابع «setApiUrl» ← ▷ Run.
    (این کار علاوه بر آدرس، شناسه‌ی ورود با گوگل را هم ثبت می‌کند.)


مرحله ۶ — انتشار دوم: «Madar Google» (ورود با گوگل، تقویم و Meet)
-----------------------------------------------------------------
 1. Deploy ← New deployment ← ⚙️ ← Web app
      Description:     Madar Google
      Execute as:      User accessing the web app
      Who has access:  Anyone with Google account
 2. Deploy ← آدرس URL را کپی و نگه دارید (برای مرحله ۸).


مرحله ۷ — چک با diagnose
------------------------
 فهرست توابع ← diagnose ← ▷ Run ← پایین صفحه «Execution log» باید این‌ها را نشان دهد:
   نسخه‌ی Code.gs = 2.3.0
   API_URL = آدرس مرحله ۴
   GOOGLE_CLIENT_ID = یک مقدار …apps.googleusercontent.com
   GET  → 200 · {"ok":false,"error":"وارد نشده‌اید"}
   POST → 200 · {"ok":false,"error":"وارد نشده‌اید"}
 اگر GET صفحه‌ی Sign in داد ← در مرحله ۴ Who has access روی Anyone نبوده:
   Deploy ← Manage deployments ← Madar Team ← ✏️ ← Anyone ← Deploy.


مرحله ۸ — اولین ورود
--------------------
 1. آدرس Madar Team را باز کنید (بهتر است در پنجره‌ی Incognito: Ctrl+Shift+N).
 2. ورود: نام کاربری vahid.ameri و رمز Madar@1405، یا «ورود با حساب گوگل».
 ✔ چک: پایین صفحه‌ی ورود نوشته باشد v2.3.0.
 3. بک‌آفیس ← تنظیمات ← کارت Google:
      • «لینک ورود با گوگل (Madar Google)» = آدرس مرحله ۶ ← ذخیره
      • «رمز عبور تیم» را عوض کنید.


مرحله ۹ — تعریف دپارتمان (همه از بک‌آفیس)
------------------------------------------
 1. بک‌آفیس ← دپارتمان و دسترسی:
      ردیف «جلیل علیزاده» ← ✏️ ← ایمیل گوگلش را وارد کنید ← ذخیره.
      (سطح دسترسی‌اش «CPTO · همه‌چیز» است.) بقیه‌ی افراد دپارتمان را هم اینجا اضافه کنید؛
      لازم نیست وارد شوند، فقط مسئول تسک و حاضر جلسه می‌شوند. ایمیلشان برای دعوت‌نامه‌ی تقویم لازم است.
 2. بک‌آفیس ← سمت‌ها و سازمان:
      «تیم‌های دپارتمان»: لاین‌ها، مدیران محصول، CRM و عملیات، داده و… را تعریف کنید (اسم و رنگ).
      هر تیم در صفحه‌ی «تیم‌ها و پروژه‌ها» با پروژه‌های زیرش دیده می‌شود.
      سمت‌ها، گروه‌های سازمانی و انواع جلسه هم همین‌جاست.
 3. بک‌آفیس ← اشخاص و رده‌ها:
      • رده‌ها، SLA (ساعت) و وزن اولویت را تنظیم کنید (پیش‌فرض: مدیرعامل/هیئت‌مدیره ۴ ساعت،
        معاون ۲۴، مدیر ۴۸، کارشناس ۷۲).
      • اشخاص را یکی‌یکی اضافه کنید یا با «چسباندن از اکسل» گروهی وارد کنید
        (ستون‌ها: نام، سمت، تیم/سازمان، رده، ایمیل، تلفن).
 4. بک‌آفیس ← تنظیمات:
      • وضعیت‌ها، پرچم‌ها، هشدار راکد و انسداد، فیلدهای تسک.
      • نمای کلی: کدام بخش‌های داشبورد نمایش داده شوند و به چه ترتیبی.
      • سلامت تیم: از چند درصد معوق/مسدود، تیم زرد یا قرمز شود.
      • لایه‌های تقویم: ددلاین تسک، جلسه، پیگیری، موعد میزیتو، رویدادهای دیگر تقویم گوگل.

 5. محصولات و پروژه‌ها (تیم‌ها و محصولات ← محصول جدید):
      • «محصول» همیشگی است (مثل کلاسا): تاریخ پایان ندارد و سلامتش از کارها، ریسک‌ها،
        شاخص‌ها (KPI)، OKRهای مرتبط و گزارش وضعیت هفتگی حساب می‌شود.
      • «پروژه» شروع و پایان دارد و سلامتش با زمان‌بندی هم سنجیده می‌شود.
      • برای هر محصول چند شاخص (KPI) با هدف تعریف کنید و هر چند وقت مقدار جدید را ثبت کنید.
 6. برنامه‌ریزی فصلی:
      • OKR تیم‌ها: برای هر تیم در هر فصل چند هدف (Objective) و زیر هر هدف چند نتیجه‌ی کلیدی
        (Key Result) با مقدار هدف، وزن، مسئول و لینک میزیتو تعریف کنید. وزن همه‌ی نتایج کلیدی یک تیم
        در فصل روی هم باید ۱۰۰ شود (فرم، باقی‌مانده را نشان می‌دهد). هر هفته «چک‌این» بزنید
        (مقدار + اطمینان + یادداشت) تا روند ساخته شود؛ روی هر نتیجه‌ی کلیدی بزنید تا روند، مستندات،
        یادداشت‌ها و تسک‌هایش را ببینید. تسک‌ها را در پنل تسک به یک نتیجه‌ی کلیدی وصل کنید.
      • اسپرینت‌ها (تیم فنی): در تنظیمات ← «اسپرینت» تیم‌هایی که اسپرینتی کار می‌کنند، طول اسپرینت
        و پیشوند کلید (مثل TECH) را تعیین کنید. در «اسپرینت‌های تیم فنی»: بک‌لاگ بسازید، به هر کار
        امتیاز بدهید، کارها را به اسپرینت برنامه‌ریزی‌شده ببرید، «شروع اسپرینت» بزنید و در پایان
        «بستن اسپرینت» (کارهای ناتمام به اسپرینت بعد یا بک‌لاگ می‌روند و رترو ثبت می‌شود).
        گزارش هر اسپرینت (تعهد، انجام‌شده، تغییر دامنه، برن‌داون، مسدودها) برای CPTO قابل دیدن و
        چاپ است و خلاصه‌ی اسپرینت در جریان در ایمیل صبحگاهی هم می‌آید.
      • برنامه‌ی تیم‌ها (طراحی، محصول و تیم‌های بدون اسپرینت): برای هر تیم آیتم‌های برنامه با شروع، پایان،
        مسئول، وضعیت و پیشرفت بسازید (اختیاری: محصول و نتیجه‌ی کلیدی مرتبط). خط زمانی فصل، تأخیر و
        جابه‌جایی از تعهد اول را نشان می‌دهد. هر هفته در صفحه‌ی هر آیتم «وضعیت این هفته» را بنویسید؛
        همین خط در «گزارش برای CPTO» می‌آید.
      • گزارش برای CPTO: یک صفحه‌ی قابل چاپ برای جلیل با وضعیت همه‌ی تیم‌ها (OKR، کارهای در جریان،
        در خطر، انجام‌شده، شروع‌های بعدی، اسپرینت تیم فنی و ریسک‌های اصلی).
      • توزیع منابع: سهم وقت هر نفر برای هر محصول در فصل. بیش از ظرفیت قرمز می‌شود.
        «کپی از فصل قبل» تخصیص‌های فصل قبل را برای فصل جدید می‌سازد.
      • میزیتو: آدرس میزیتو، وضعیت‌ها، دسته‌ها، نوع اقدام، فرمول اولویت P0 تا P3، متن یادآوری.
      • اتوماسیون‌ها: هرکدام را که می‌خواهید روشن کنید. برای خلاصه‌ی صبحگاهی (۷:۳۰) یک بار
        در Apps Script تابع installAutomations را Run کنید.


مرحله ۱۰ — آوردن داده از شیت‌های قبلی (اختیاری)
-----------------------------------------------
 بک‌آفیس ← ایمپورت. ترتیب پیشنهادی:
   1. اشخاص   2. تسک‌ها (My Tasks و Archive)   3. پیگیری‌ها (Follow-Up)   4. میزیتو (QUEUE)
   5. لاگ قدیمی (تب Log: یادداشت‌ها و تغییرات وضعیت به تاریخچه‌ی همان تسک‌ها وصل می‌شوند)
 برای هرکدام: «لینک گوگل‌شیت» را بچسبانید ← «خواندن تب‌ها» ← تب را انتخاب کنید ←
 ستون‌ها و مقدارها را بررسی کنید (حدس زده شده) ← پیش‌نمایش ← ایمپورت.
 • ردیف‌های تکراری رد می‌شوند. در میزیتو، ردیف‌های یک تسک یکی می‌شوند و بقیه به ترد آن می‌روند.
 • هر ایمپورت پایین همان صفحه با «برگرداندن» قابل حذف کامل است.
 • حساب صاحب اسکریپت باید به آن شیت‌ها دسترسی داشته باشد.


مرحله ۱۱ — لینک برای CPTO

 آدرس Madar Team را برای CPTO بفرستید. او با «ورود با حساب گوگل» (همان ایمیلی که در مرحله ۹ ثبت شد)
 یا نام کاربری jalil.alizadeh و رمز تیم وارد می‌شود. اولین بار گوگل از او اجازه می‌خواهد
 (Advanced ← Go to Madar ← Allow).


ایمپورت میزیتو با Claude
-------------------------
 1. در مدار: میزیتو ← دکمه‌ی «ایمپورت از Claude» ← «میزیتوی چه کسی» و «از تاریخ» را ببینید ← «کپی متن آماده برای Claude».
 2. میزیتو را در کروم باز کنید ← افزونه‌ی Claude را روی همان تب باز کنید ← متن را بچسبانید و بفرستید.
    اگر بخش‌بخش جواب داد، بعد از هر بخش بنویسید «ادامه» تا تمام شود.
 3. همه‌ی جواب‌ها را (پشت سر هم، با همان ```json ها) کپی کنید و در کادر ایمپورت مدار بچسبانید.
    ✔ چک: زیر کادر تعداد تسک، لینک، منشن و کامنت بیاید و با شمارشی که Claude در آخر گفته بخواند.
 4. «ایمپورت».
 • ایمپورت دوباره چیزی را دوبار اضافه نمی‌کند (با لینک یا عنوان تسک یکی می‌شود)؛ فیلدی که Claude خالی گذاشته، مقدار قبلی را پاک نمی‌کند.
 • اگر از ایمپورت‌های قبلی ردیف تکراری مانده، همان‌جا «یکی کردن تکراری‌ها» را بزنید.
 • تسکی که بعداً دوباره منشن شود، همان ردیف می‌ماند: SLA از منشن تازه حساب می‌شود و اگر بسته یا «منتظر» بود دوباره باز می‌شود (نمای «منشن دوباره»).
 • SLA و رده از کسی می‌آید که منشن کرده؛ نام‌ها به افراد شناخته‌شده‌ی مدار وصل می‌شوند (بک‌آفیس ← اشخاص).
 • لینکی که خودتان روی یک مورد بگذارید با ایمپورت بعدی پاک نمی‌شود.
 • شروع از صفر: پایین همان صفحه «پاک کردن داده‌های میزیتو» ← کلمه‌ی «پاک کن».

---------------------------------------------
 1. Code.gs و Index.html (و اگر عوض شده appsscript.json) را مثل مرحله ۲ جایگزین کنید ← Ctrl+S.
 2. یک بار setup را Run کنید (تب‌ها و ستون‌های تازه ساخته می‌شوند؛ داده‌ها دست نمی‌خورند).
    (از 1.5.0 و 1.6.0: setup تب‌های MizitoComments، Cartable و Todos و ستون‌های تازه‌ی Mizito و MizitoMentions را می‌سازد.)

    همین کار را برای Madar Google هم بکنید.
